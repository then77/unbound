## Glossary

| Term | Meaning |
|---|---|
| **App** | The application requesting authentication and approved identity data. |
| **App origin** | The HTTPS origin used to identify the public client, bind the callback, and scope the pairwise identity. |
| **Provider** | An external sign-in provider—currently Google, GitHub, or Discord when configured—that authenticates the user to Unbound. |
| **Authorization code** | A short-lived encrypted value returned to the app callback and exchanged for a token. |
| **Token** | A short-lived signed JWT bearer token issued after a successful code exchange. |
| **Scope** | A requested category of access: currently `openid`, `profile`, or `email`. |
| **Pairwise subject** | The app-scoped Unbound user ID in the token’s `sub` claim. Different app origins receive different values. |

Unbound exposes OIDC-style discovery, JWKS, authorization, token, and userinfo endpoints. This describes the current implementation, not full OpenID Connect certification or generic client compatibility.
